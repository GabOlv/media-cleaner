## Objetivo

Transformar o aplicativo em um utilitário de revisão de mídias simples, moderno e acessível. O usuário poderá selecionar somente os arquivos que deseja excluir; arquivos não selecionados serão ignorados nas próximas revisões, até que a lista de ignorados seja redefinida.

A interface deve ser compacta, clara e séria, sem robô, XP, níveis, pontos, gamificação, textos de pressão ou botões visualmente exagerados.

## Direção visual escolhida

Direção: **utilitário calmo**.

Princípios:

1. Uma ação principal por tela.
2. Conteúdo e tipografia fazem a hierarquia; cartões e ícones são usados somente quando ajudam a interação.
3. Controles compactos, com área de toque acessível de aproximadamente 44–48 px.
4. Neutros claros com verde pastel como identidade visual calma e durável.
5. Texto escuro em estados selecionados; nunca usar texto branco sobre laranja claro.
6. Sem sombras decorativas, gradientes, hero ilustrado ou excesso de estatísticas.
7. Toda ação destrutiva deve ser explícita, reversível quando possível e confirmada sem linguagem de culpa.

## 3. Revisão por seleção

Alterar a Revisão para uma lista de candidatos:

1. Buscar até a quantidade diária configurada.
2. Mostrar cada mídia com prévia, nome, data e tamanho conhecido.
3. O usuário marca somente os arquivos que deseja excluir.
4. Arquivos não marcados não são excluídos.
5. O botão inferior mostra `Excluir selecionados (N)` quando houver seleção.
6. Se nenhum item estiver marcado, mostrar `Concluir revisão`.
7. Confirmar exclusões com quantidade e tamanho conhecido.
8. Excluir somente os selecionados após confirmação real do sistema.
9. Registrar itens não selecionados como ignorados somente ao concluir a revisão.
10. Se uma exclusão falhar, o item permanece pendente e não entra na lista de ignorados automaticamente.

A seleção deve usar checkbox, borda e texto, não somente alteração de cor.

## 4. Lista de itens ignorados

Separar no modelo:

- Itens ignorados: o usuário decidiu não excluir.
- Itens excluídos: exclusão confirmada pelo sistema.
- Itens revisados na sessão diária.

Em Ajustes, abaixo de “Pastas protegidas”, adicionar:

`Redefinir lista de ignorados`

Comportamento:

- Mostrar quantos itens estão ignorados.
- Pedir confirmação explicando que nenhum arquivo será excluído.
- Limpar somente os IDs ignorados.
- Manter pastas protegidas, preferências, histórico de exclusões e contadores.
- Os itens poderão aparecer em futuras revisões.

Migração: IDs do modelo anterior devem ser tratados conservadoramente como ignorados, pois o formato antigo não diferencia com segurança todas as decisões.

## 6. Lembretes diários

Substituir o campo de texto de horário por uma interface de horários nativos.

Modelo recomendado:

```ts
reminder: boolean;
reminderTimes: number[]; // minutos desde 00:00, entre 1 e 3 horários
```

Migração:

- O antigo `time: "20:00"` vira `reminderTimes: [1200]`.
- Preferências antigas continuam preservadas.

Interface:

- Alternância para ativar/desativar.
- Escolha: `1 vez`, `2 vezes` ou `3 vezes`.
- Uma linha para cada horário.
- Tocar na linha abre um modal com relógio de hora e minuto.
- Ao salvar, o modal fecha e a linha mostra o horário formatado.
- Remover o botão antigo “Salvar horário”.

No Expo SDK 57, preferir `@expo/ui` com `DateTimePicker` em modo diálogo no Android e controle nativo equivalente no iOS. No navegador, usar uma alternativa acessível com seletores de hora e minuto.

### Conflitos de horários

Processar os horários em ordem:

```text
se um horário já existir:
    adicionar 10 minutos
    repetir até encontrar horário único
    usar módulo 1440 ao atravessar meia-noite
```

Exemplos:

```text
08:00, 08:00          → 08:00, 08:10
08:00, 08:00, 08:10   → 08:00, 08:10, 08:20
23:55, 23:55          → 23:55, 00:05
```

Mostrar uma mensagem acessível quando houver ajuste automático:

“O segundo lembrete foi ajustado para 08:10 para evitar horários iguais.”

Agendar um gatilho diário independente para cada horário. Não usar mais o nome de canal `daily-robot`; usar um nome neutro, como `daily-review`.

Não cancelar notificações de outros recursos arbitrariamente; filtrar e cancelar somente as notificações pertencentes ao MediaCleaner.

## 7. Demonstração por flag

Criar uma configuração central, por exemplo:

```ts
features.demoMode
```

Regras:

- A demonstração aparece somente em Ajustes.
- Se a flag for `false`, a linha, o ícone e todos os acessos à demonstração desaparecem.
- Dados de demonstração continuam isolados dos dados reais.
- No Expo Go, a Revisão deve explicar a limitação e não iniciar a demonstração automaticamente.

## 8. Validação

Executar após a integração:

```sh
npm run typecheck
npm test
npm run test:ui
npx expo-doctor
npx expo export --platform android --output-dir artifacts/android
```

Cobrir nos testes:

- 1, 2 e 3 lembretes.
- Horários duplicados e ajuste de 10 minutos.
- Conflitos próximos da meia-noite.
- Migração do horário antigo.
- Quantidade personalizada.
- Contraste do valor selecionado.
- Navegação voltar em todas as telas internas.
- Cancelamento de exclusão.
- Exclusão parcial com falha.
- Itens não marcados entrando nos ignorados.
- Redefinição dos ignorados sem apagar outras preferências.
- Demonstração apenas em Ajustes.
- Flag desligada ocultando completamente a demonstração.
- Ausência de termos antigos de gamificação.

Revisar visualmente em:

- 320 × 640
- 390 × 844
- 768 px
- 1024 px
- Texto ampliado para 150%
- Navegação por teclado no navegador
- Redução de movimento
- Ausência de rolagem horizontal

Testar permissões, exclusão real e notificações em uma build Android própria. Expo Go no Android não consegue fornecer o acesso amplo a fotos e vídeos exigido pelo aplicativo.

## Critério de conclusão

O plano estará concluído quando:

- a Revisão permitir selecionar arquivos para exclusão;
- arquivos não selecionados forem ignorados em revisões futuras;
- a lista de ignorados puder ser redefinida;
- os lembretes aceitarem 1, 2 ou 3 horários sem duplicidade;
- os horários forem escolhidos por relógio/modal;
- o botão voltar funcionar entre todas as telas internas;
- a interface tiver laranja pastel, controles compactos e contraste correto;
- a demonstração estiver somente em Ajustes e controlada por flag;
- todos os testes e revisões de layout passarem.
